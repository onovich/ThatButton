# 微信小游戏升级页 v23：按模拟器截图严格复核

日期：2026-09-30

## 复核输入与结论

用户提供微信开发者工具的 328×710 画面。三路独立观察分别核对原画与运行画面、可切图资源、`drawUpgrade()` 实现，结论一致：旧运行画面与浏览器预览基本相同，差距来自 v22 整页设计稿只有标题被切图接入；气泡、状态板、卡壳、图标和爆发线都由简化的 Canvas 形状与系统字形绘制。原先底部绿叶出现过早，角色相对设计稿偏小。

对照稿：[v22 整页设计](../ports/wechat/assets/concepts/2026-09-30/upgrade-v22/upgrade-fullscreen-study.png)。原 v15 升级页另有 [完整原画](../ports/wechat/assets/concepts/2026-09-29/v15-art-polish/upgrade-v15-choices-abc-390x844.png)，但它是更素的暖白版本；这次按 v22 的黄色舞台方向完成分层。

## 图层与实现

| 部位 | v23 处理 | 原因 |
| --- | --- | --- |
| 标题 | 保留 v22 透明美术字 | 已和整体稿一致 |
| 三种已有升级卡 | 从整页稿按轮廓切出完整透明卡面，含固定文案、立体图标、高光、厚侧壁和双爆发线 | 这些内容与数值在当前游戏里固定；避免系统字形及简化 Canvas 图形偏差 |
| 第四种进度卡 | 以三张原画卡为严格参考，使用内置 `image_gen` 补同族紫色卡，再裁剪、量化 | 原整页稿没有第四种升级 |
| 对话气泡 | 从整页稿切出带尾巴及固定提示的透明层 | 恢复异形轮廓和红/蓝分色文字 |
| 状态板及体力徽章 | 切出状态底板与粉色心形徽章；分数、当前/最大体力保留 Canvas 实时文字 | 数值随局内变化，不能烘焙在图片里 |
| 角色 | 仍用已验收 v11 `running-pair.png`，只调尺寸与位置 | 整页设计稿重绘的角色与 v11 基准不完全一致，未采用 |
| 背景 | 复用现有黄色舞台图，通过裁取重排使绿叶只出现在底部 | 不新增不一致的整页背景，也避免绿叶压住第三张卡 |
| 短屏底部提示 | 浅色小底片承载动态提示 | 320×568 时底部空间不足，保证文字对比 |

切图可由 [`prepare-upgrade-v23.py`](../ports/wechat/scripts/prepare-upgrade-v23.py) 重建，原画切片和第四种卡的生成母图位于 `ports/wechat/assets/concepts/2026-09-30/upgrade-v22/`；游戏只加载 `ports/wechat/assets/runtime/upgrade-*-v23.png`。四张卡面共用固定数值文案；若代码中的升级数值发生变化，渲染器会改用动态文案后备绘制，避免展示错误数值，届时应重做相应切图。

第四种卡的最终生图提示词：以 v22 的粉、黄、青三张卡为严格视觉参考，把粉色卡编辑成同尺寸的紫色厚侧壁奶油白实体卡；左侧薰衣草色亮面方块内为深蓝四角星，右侧两道紫色爆发线；标题精确写“清轮进度加成”，副标题精确写“每次清轮，挑战进度额外 +4”；保持深蓝粗描边、卡面渐变、高光、阴影、字重和元素相对位置，不添加角色及其他界面元素。使用内置 `image_gen`，最终图经检查中文与形状后裁切入包。

## 画幅验收

- 用户截图对应状态的 [328×710、分数 1180、体力 10/100、同顺序三卡预览](../ports/wechat/tests/visual-evidence/v23final2-upgrade-score1180-simulator-order-hp10-328-safe54.png)。对比 v22，卡面、气泡、状态徽章和底部背景均已按画稿分层；角色依 v11 造型适配，保留原画轮廓。
- [320×568 窄屏](../ports/wechat/tests/visual-evidence/v23final2-upgrade-320-safe46.png)、[390×844 常规屏](../ports/wechat/tests/visual-evidence/v23final2-upgrade-390-safe64.png)及 [第四种紫色升级卡](../ports/wechat/tests/visual-evidence/v23final2-upgrade-fourth-390-safe47.png)已检查卡片边界、标题、角色、底部提示。
- `ports/wechat: npm run check`、根项目 `npm run validate` 与 `npm run build` 通过；v11 角色基准校验通过。当前小游戏构建目录为 4,154,822 字节，低于 4 MiB 限制，余量 39,482 字节；后续音频或图片改动需要再次核对包体。

浏览器证据使用与微信游戏相同的 Canvas 渲染器及资源，并模拟用户截图的尺寸和安全区；本次没有取得重新编译后的微信开发者工具画面，因此模拟器实时表现仍以用户重新编译后的画面为最终确认。

## 2026-09-30 复查与待验收项

重新运行 `ports/wechat: npm run check`、根项目 `npm run validate` 和 `npm run build`，均通过。当前构建仍为 4,154,822 字节，距 4 MiB 上限余 39,482 字节；音效与背景音乐契约检查包含在根项目验证中。

开发者工具已打开且自动化端口可连接，但小游戏截图与运行时表达式均在等待模拟器响应时超时。开发者工具的 `cli agent tool` 入口又要求 `app.json`，而此工程是只有 `game.json` 的小游戏；因此未能取得真实模拟器的 v23 截图。下一项验收是重新编译后，在模拟器核对首页、局内、四种升级卡、结算页和不同安全区；随后用 iPhone 与 Android 真机各走一遍核心流程及音乐设置。

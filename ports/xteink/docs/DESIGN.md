HTML 数学演示与 Lua 设备版共用 480×800 主面板比例：20px 留边，顶部只显示“禁止按下”；黑块位于 (20,88)，440×160；九键从 (20,272) 起，140×112，列距 8、行距 12；九宫格下方不再显示任何安全/危险结果或原因解释（0.1.2 修订）。去掉游戏名称、版本、检修编号、教学提示、底部三个按钮和底栏分隔线。

形状直接称圆形/三角形/方形/星形，数字条件称“带xx的形状”。AND 为“以及”，OR 为“或”，NOT 为“除了……之外”，对整个组合的判定取反。组合按形状、连接词、数字条件三行展示，不解析中文来做判定。HTML 的设置留在设备画布之外；Lua 用 Back 进入/离开独立设置页，主画面只有九个可触摸按钮。点击后也不增加结果说明文字。

Lua 的条件文字使用本地生成的有限 28px 黑白字形并合并绘图矩形，避免假设 g:text 支持字号。字形来源和生成方式在 scripts/generate-glyphs.py，已纳入最坏帧命令预算检查。网页抗锯齿与真实 1bit 显示的差异仍存在，但信息结构、留白与几何坐标一致。

## 当前决定：放弃纹理，采用数学条件（2026-09-20）

用户明确取消纹理路线；A–D 组别与纹理实验均为废弃的探索记录，不再参与当前设计或研发验收。当前入口为 [数学条件试玩](../design/math-study.html)，旧纹理页面自动转向该入口。

设备版通过数字的数学性质提供规则变化：n 的倍数、尾数为 n、十进制包含数字 n、奇数、偶数、质数、合数。形状属性必须保留：圆形、三角形、方形、星形与数字共同构成按钮。放弃的是颜色替代方案，不是形状。当前原型支持只看数字、只看形状、形状且数字、形状或数字。Web 版保持原样。

数值域为 1–99 正整数，不显示前导零。尾数明确指个位，包含检查任意位，参数数字允许 0；倍数参数首版为 2–9。质数定义为大于 1 且恰有两个正因数；合数为大于 1 且有其他正因数。**1 既非质数也非合数，2 是唯一偶质数。** 因此“非质数”不可直接改写成“合数”；“奇数”不可直接改写成“质数”。

固定试玩面板包含 1、2、9、17、21、27、49、70、72，覆盖 1 的特殊情况、偶质数、奇合数、平方数与尾数/包含反例。按键反馈说明整除余数或因数分解，不只说对错。没有匹配的实验参数会提示；正式关卡生成必须保证有安全键也有危险键。

难度顺序：奇偶/尾数 → 包含 → 小倍数 → 质数/合数 → 最多两条件的且/或/非。质数识别先在 1–30 引导，再扩大到 99；不要把判断负担变成突然的心算考试。后续可考虑大小、区间、平方数，但未纳入本轮实现。

设备规则 AST 新增 prime/composite，Lua 与 JS 对照覆盖 1、2、平方合数和 97 等边界。生成器避免偶数与 2 的倍数、尾数 0 与 10 的倍数等等价重复；同一面板内需检查复合条件是否退化或无解。原型已支持形状与数学条件的且/或组合；多重数学条件、非条件和生产关卡生成仍是后续项。

## 最新修订：纹理与数字（2026-09-20）

用户认为 A–D 组别生硬，因此下文组别方案保留为第一稿历史，不再作为推荐方向。新增 [交互实验](../design/texture-study.html)：同一数字比较光面、横纹、斜纹、点纹、网格、交叉纹；可选底部边带、整个表面、无纹理，疏纹/密纹，显示/隐藏名称。9 键面板使用前四种，后两种仅对照，避免同时引入六个类别。纹理方案尚待试玩选择。

初步偏好疏纹边带：形状、数字与纹理各占自己的空间；整面纹理作为对照，数字白色铭牌和轮廓白边避免背景穿字。网格/交叉纹比前三种有更高的视觉密度，不作为首选。SVG 图案只用于设计；Lua 需合并绘图命令并统计预算。浏览器预览不能证明真机残影或刷新成本。

### 数字条件

| 条件 | 精确定义（正整数 x） | n 的设计范围 | 示例 |
|---|---|---|---|
| n 的倍数 | x % n == 0 | 2–9 | 3 的倍数：12、21、27、30、42、72 |
| 末位是 n | x % 10 == n | 0–9 | 末位 7：17、27；70 不满足 |
| 数字中含 n | 十进制表示含该字符 | 0–9 | 含 7：17、27、70、72；重复出现也只算匹配一次 |
| 奇数 | x % 2 == 1 | 无参数 | 17、21、27 |
| 偶数 | x % 2 == 0 | 无参数 | 12、20、30、42、70、72 |

建议入门保留 1–9 与形状/奇偶，随后引入 10–99（整个目录限制为 1–99，无前导零）。仅有一位数时“末位 n”“含 n”“等于 n”完全等价，不应包装成三种不同难度。先用“末位”这种视觉判断，再教 2/5/10 的倍数直观规律，后续开放 3/4/6 等；实验控件先提供 2–9，不把 10 的倍数和末位 0 当成两种独立内容。

规则生成必须保证至少一个安全键和一个危险键，限制危险密度并覆盖临界反例；固定实验面板参数不保证每个 n 都有匹配，实验中会提示，生产生成器必须过滤。避免等价规则制造假难度：偶数=2 的倍数，奇数=非偶数，末位 0=10 的倍数；“末位 7 且 含 7”后半句冗余；“3 的倍数 且 末位 5”才是需要同时检查的条件。

AND/OR/NOT 一次只增加一层，先单属性，再形状＋数字，最后按辨识结果考虑纹理＋数字。不叠加两位数、复杂算术、新纹理与否定式作为同一入门关。边带纹理是可选第三维，不要求机械补足 Web 的四种颜色。

新实验的纯数字谓词位于 `design/number-rules.js`，不影响 Web 核心。后续 Lua 使用同一结构化规则字段及固定对照样例，不解析中文。概念稿展示“数字中含有 7”，避免“带 7”的口语与纹理“带斜纹”混淆。

## 主题与取舍

“反应堆检修终端”：读禁止条件，逐个解除安全开关，完成面板后打击失控核心。对象是用触屏或实体键游玩的 X4 Pro 玩家；单屏首要任务是让规则和每颗按钮的三个属性同时可读。

考虑过纯黑终端、纸面作业单、工业面板三条方向。纯黑大面积反转不利于稳定反馈，作业单丢失原作按钮感；采用白底工业面板，仅危险指令和仪表使用黑块。核心标识是“封闭几何壳体里的大数字＋下方电路组铭牌”。不复用参考游戏的皇冠、扑克和棋盘语言。

## 玩法改编

| Web | 设备设计 |
|---|---|
| 红蓝黄紫 | A/B/C/D 电路组，双写“组 A”等标签；映射 red→A、blue→B、yellow→C、purple→D |
| 颜色条件 | 同一谓词结构更换可见术语，如红且三角→组 A 且三角；不是删掉颜色维度 |
| 圆 / 三角 / 方 / 星＋数字 | 保留，几何轮廓独立绘制，数字留在内部白色区；星形小尺寸需单独验收 |
| 实时倒计时与连击窗口 | 首版去除墙钟惩罚；连续正确操作形成连击，错误清零，导航和读帮助不消耗资源 |
| 清空安全按钮 | 保留；危险按钮可以有多个，全部安全按钮完成即结算，无需按危险键 |
| 玩家 / 敌人 HP | 保留概念，数值另调；先验证单局，再接入长线战斗 |
| 移动按钮与干扰闪烁 | 首版移除；暂不以另一种 Hazard 替代，避免同时改变太多维度 |
| 粒子、音频、浮字、震动 | 静态结果与保留到下一操作的文字；不以音频/震动作为必需信号 |
| 三选一升级 | 后续只保留静态属性选项；延长时间类升级不能原样迁移 |

语义映射必须发生在数据层，不能只替换说明文字而继续用颜色做渲染。JS 条件生成使用闭包，导出时应提供结构化 rule AST 或完整按钮＋预期危险 ID；Lua 不解析中文自然语言判定答案。Web 的 Host Bridge 是 JS 调用边界，不是假定设备能运行 WebView 的依据。

概念稿演示规则为“组 A 且三角”，九键中危险键为 1、9，其余 7 键安全。3 格护盾；每个危险键首次误按扣 1 格并锁定，不会重复扣血；连续正确操作计数、错误清零。清完安全键显示完成。这里只验证识别和操作，不用这组数值宣称完成战斗平衡。

## 1bit 视觉规范

- 设备仅纸白 0 / 墨黑 15。设计不添加灰度、渐变、模糊和半透明；浏览器文字抗锯齿不等于设备原生 1bit 字体。
- 展示数字：最终使用手工 5×7 或更清晰点阵整倍数放大；原型暂用本机等宽字。中文暂用系统无衬线字体代替宿主字形，正式开发实测换行和宽度。
- 标题 28px 视觉量级，指令 22–24px，正文 18–20px；这些是布局目标，不是假设 g:text 有字号参数。
- 待操作为黑边白面；已安全解除为“已解除”与黑色短横，危险误按为“已锁定 / 误按”。不把焦点反白当作危险含义。
- 键盘焦点用外侧四角或双框，与完成标记分开；触摸切换后隐藏键盘焦点。图形轮廓和组标签始终保持可读。
- 不采用连续扫描线或背景抖动。若教学未来需网纹，只覆盖非目标区域，测原生像素、整数缩放和真机；不凭缩小截图判断条纹算法。

## 输入、反馈与教学

触摸 tap 直接按下；不要求双击、长按或悬停。危险键误按后显示具体原因，结果保留到下一有效操作。安全键不消失、不重排。重复激活已处理键不扣资源、不重绘。

方向键按空间邻居移动，OK 激活，Back 关面板或回菜单。被禁用目标从可操作焦点序列排除，菜单/结算/教学出现时底层不可点击；在最外层 Back 不调用应用退出。返回游戏恢复焦点与当前局。

首次新游戏提供“边玩边学 / 直接开始”，不先展开长文。三段最短练习：①读“禁止”并点一个安全键；②不高亮答案，让玩家独立完成剩余安全键；③看完成条件并开始正式局。操作成功直接推进，只在章节完成确认。复杂的 且/或/非 放在随时可查规则中，后续独立练习。

教学和正式局对象分开，教学中禁用再次进入，误触不改正式护盾、记录或关卡。退出、重练入口始终可用。概念稿目前展示这条短流程；正式实现还需完整的首次邀请和教学偏好存储。

## 尚需用户试玩与真机决定

回合制是否损失原作紧张感；A/B/C/D 的识别负担；形状与数字的组合是否清楚；按错只扣血是否足够有代价；常用触区的物理尺寸。先试玩再调平衡，不直接把 Web 秒数改成随意的步数倒计时。

# 微信小游戏内测诊断

## 玩家如何使用

1. 首页进入「设置」，点击「内测诊断：关」。
2. 选择「开启内测诊断（仅本次运行）」并确认，然后正常试玩。
3. 试玩结束，回到设置，选择「关闭内测诊断并保存报告」。
4. 选择「复制最近内测报告」，将剪贴板中的 JSON 发给开发者，并附上试玩时长、发热体感及发生问题的关卡。

「关闭诊断并清除内测记录」仅删除诊断报告，不影响最高纪录、声音等游戏设置。关闭采集后仍可复制最近保存的报告。

## 默认关闭与开销约束

- 普通启动默认关闭，开关不持久化；退出并重新启动游戏后恢复关闭。切后台再返回属于同一次运行，不会重置开关。
- 开发者显式传入启动参数 `perf=1` 时开启，日常试玩请使用无此参数的启动方式。
- 关闭时不创建采集器、不初始化性能时钟、不创建诊断定时器、不进行性能采样或自动写入报告。绘制路径仅保留空值判断。
- 关闭正在运行的诊断时，保存一次报告并释放采集器，取消尚未执行的时钟校准任务。
- 开启后有少量测量开销，因此诊断结果应结合关闭模式下的体感比较，不能视为零开销测量。
- 不增加屏幕性能浮层，不改变分辨率、帧率、动画、输入判定或游戏计时。

## 报告内容与边界

按页面及局内场景记录 RAF 回调间隔、超过 34/50/100ms 的次数、同步绘制提交耗时、文字绘制次数及图集/故障效果相关计数。设备信息仅选择机型、系统、平台及画布尺寸、像素比等技术字段，不采集玩家身份信息。

每个场景、每个耗时序列最多保留最近 256 个样本；分位数只代表这批近期样本。累计数量与均值另行记录。后台间隔和场景切换间隔不纳入连续 RAF 间隔。

RAF 回调间隔不是屏幕实际呈现 FPS；同步绘制提交耗时不是 GPU 完成耗时。CPU 使用率、温度、GPU 耗时和内存占用没有可靠采集值，报告中标为不可用，不用估算值冒充实测值。

报告保存在本机存储 `thatbutton.wechat.performance.v1`，最多保留 3 次会话。开启期间切后台、手动导出及关闭时保存，不逐帧写盘、不逐帧打印日志、不自动联网上传。复制需玩家主动操作。

## 验证记录（2026-10-02）

自动化覆盖默认关闭、取消开启、确认开启、关闭停止计数、关闭后导出、新实例默认关闭、清理不影响游戏存档、校准定时器释放、后台间隔排除、采样边界及复制失败处理。设置入口在 320×568 和 390×844 尺寸下进行命中区域检查。

微信原生操作菜单与剪贴板交互，以及开启诊断的实际设备开销仍需真机验证。建议同一设备分别关闭/开启试玩相近关卡，记录时长和发热体感；开发者工具下的结果与普通试玩结果分开保存。

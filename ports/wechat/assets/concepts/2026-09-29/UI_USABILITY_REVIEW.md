# v11 运营可用性评审与 v12 修订

用户授权将当前原画交给「小游戏运营」负责人评估。对方实际查看了 v11 三屏、透明角色与造型基准；反馈指出：首页「开始游戏」、结算「再来一局」和脑手搭档互动可以保留。以下为按优先级整理的静态稿问题与已制作的 v12 概念修订。

| 优先级 | 评审发现 | v12 处理 |
|---|---|---|
| P1 | 局内底栏五列过挤，角色装饰与小字争空间 | 底栏改成「我方」与「考官」两组状态卡；在局内省去两位装饰性小角色，保留首页、结算和分镜中的角色。 |
| P1 | 连击只显示次数；「威力 +3」语义不清 | 显示「连击 4」「剩余 2.1 秒」「伤害加成 +3」。数值为静态示例，实装应读取真实连击窗口和伤害加成。 |
| P1 | 已完成按钮仍像未按下，主要靠小勾区分 | 已按的紫方 12、红圆 10、蓝三角 02 采用下沉面与内阴影，保留原属性色和勾；其余未按按钮维持同一外观，不预示安全答案。 |
| P2 | 黄色 04 的图形是白色，与黄色 05 的深蓝星不一致 | 黄色 04 的圆形改为深蓝。 |
| P2 | 结算「最后规则」缺少禁按语义 | 改为「当时别按：」。体力耗尽只是当前示例，超时、误按、反击等实际结束原因需按真实结果呈现。 |

[v12 PNG](hybrid-ui-v12-usability.png) 由 [可编辑 HTML/SVG 图层](ui-usability-v12.html)叠加在 [v11 造型基准](hybrid-ui-v11-unified-thin-rim.png)上导出。v11 文件未改动；首页、结算双人组及底部分镜区域与 v11 像素一致。[透明结算角色](brain-glove-b-caring-pair-thin-rim.png)仍是后续角色变体的参考。

**仍需实机验证：**连续点击时已按状态辨认、动效是否干扰判断、实际触摸准确性与首局理解成本。静态原画不能替代真机测试。前端还需把连击时限、伤害加成、剩余按钮数、结算原因和规则文案绑定真实状态，不应直接使用图中的示例数值。

## v12 复验后的短屏补充

运营负责人复验认为：v12 的状态分组、按钮下沉、连击说明、黄色图形和结算措辞已解决静态稿问题。剩余 P1 是 320×568 与其他短屏的实际排布：三屏图等比缩到 320px 会把底栏说明压到约 11–14px，且高度不足。

为此制作 [v13 响应式局内稿](ui-compact-v13.html)，并输出 [320×568](ui-compact-v13-320x568.png)、[360×640](ui-compact-v13-360x640.png)、[390×844](ui-compact-v13-390x844.png) 三张真实 CSS 尺寸截图。320px 稿同时容纳 9 枚按钮、较长的「颜色＋形状＋数字」禁按条件、倒计时、剩余安全数、我方体力、连击时限、伤害加成、考官耐力与反击。状态说明使用约 14px，关键数字约 16px；按钮触控面远大于 44px。示例条件只禁按红色三角形 03，3 枚安全按钮已按，因此剩余 5 枚。实际规则生成器不一定每局使用该长条件；这张图专用于压力测试。

## v13 运营复验与细节调整

运营负责人复验了 320×568、360×640、390×844 三种截图，确认静态排布可读、无内容截断，短屏 P1 已关闭。对方随后提出三项 P2：体力条应紧邻体力数值；圆形、方形应和三角形使用同尺寸图形资源；390px 长屏应按内容组分配留白。当前 v13 已逐项处理：体力条移到我方体力行，九格图形统一为 26×26 SVG，390×844 在顶部、规则与棋盘之间、棋盘与状态区之间及底部留出分层间距。规则文案现在按容器宽度自动换行，320px 截图已覆盖完整的长条件。

v13 是小屏布局方案，尚不是小游戏运行代码。还需在真机和实际 Canvas 渲染器上验证安全区域、动态规则的极端长度、触控命中、连击刷新与动画。正式按钮素材也需把弹起和按下状态制成同一套材质，消除 v12 叠加图层与原图按钮之间的细微质感差异。

# 微信文字图集内测与验收（2026-10-02）

第一批新增应用侧诊断，默认关闭。开发工具编译的启动参数设为 `perf=1` 开启，正常启动不建立统计对象、不刷日志、不自动上传，也不显示常驻浮层。设置页的「复制内测报告」主动导出 JSON；仅切后台及主动导出时保存本机快照，同一会话覆盖，最多保留三次会话。

统计按主页、设置、局内、入场、退场、交换、漂移、glitch、升级、结算与恢复等有限场景汇总。包含实际前台 RAF 回调间隔、超过 34/50/100 ms 的间隔次数、同步绘制/宿主命令提交耗时与绘制次数、fillText 次数、图集命中/回退、glitch 重建/读回。计时先使用明确的 Date.now 毫秒值；一次非阻塞 200 ms 校验将 `wx.getPerformance().now()` 增量与墙钟比较，只有单位匹配毫秒或微秒才启用并归一化，报告标明除数。不可用/单位不明仍保留 Date.now。切换计时源清除上一回调样本。setTimeout 替代 RAF 时另计 timerCallbacks，不生成 RAF 间隔。隐藏及等待继续不计入回调间隔；场景切换也不跨场景合并间隔。

总次数、累计/平均/最大值保留全会话，分位数仅使用每场景最近 256 个样本；不是全程精确分位数。没有每帧持久化、字符串日志或排序，排序仅在保存/导出时发生。GPU 呈现 FPS、CPU 百分比、温度、GPU 耗时和内存读数均明确为 null，不能从 RAF 或合成 trace 猜值。诊断自身有计数及取时开销，比较组应使用相同诊断设置。

既有 `89eab01` 的绘制合并、测量/布局缓存、隐藏/恢复调度与 glitch 缓冲复用保持。共享 Web 源码不变。此轮不发布、不更改运营配置。

## Mac / iPhone 对照步骤

1. 拉取此轮提交，在 `ports/wechat` 运行 `npm ci`、`npm run check`，导入 `build/`，记录 Git 提交、总包字节及微信/基础库/开发工具版本。原始 CPU trace 与 `ANALYSIS.md` 保留。
2. 同一 iPhone、亮度、环境、网络、保护壳与高性能模式，固定 seed，分别测普通预览及连接调试器；发热/电量对照不充电且不连接调试器，试玩 10–15 分钟。温度不可读就写未测。
3. 两组开启 `perf=1`，按相同时间线覆盖主页静置、普通局内、密集点击、换关、升级、结算、交换、glitch、后台返回；退出本局后进入设置复制报告。报告不会自动离开设备。对比各场景次数、绘制耗时、最近样本分位数及长回调间隔，不能把这些称为 GPU FPS。
4. 检查前导零、红色规则高亮、换行/居中、字号、按下/交换/出入场动效；操作命中、交换保护与 640 ms 时间补偿、音频/震动、暂停继续、重开和存档。图集失败必须可回退。
5. iPhone 17 的 48 关/2910 分与不明显发热反馈不是受控前后对照。Windows 无头测试也不能替代 Mac+iPhone 或 Android 真机收益验收。

## 本地检查

`npm run validate`、`npm run build`，`cd ports/wechat && npm run check`。诊断测试覆盖默认禁用、前台间隔与后台排除、场景切换、有界样本、本地覆盖保存、主动复制、存储失败。后续图集证据与开关参数记录于此。

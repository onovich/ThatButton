# 微信小游戏性能优化计划

## 基线与边界（2026-10-01）

用户反馈当前手机试玩体验不错，但手机发烫。当前玩法、美术、动画、音频作为保护基线，代码基线为 `3578c15`。本次仅规划，不实施运行时代码优化。发热原因尚未通过真机性能数据确认，不能承诺完全消除发热。

保持规则、随机目标、关卡安排、奖励、连击、时间补偿、命中判定、存档和 Web 端行为不变；保持 DPR、素材、动画轨迹/时长、震动、呼吸、插值、音频及 glitch 参数不变。默认不采用降分辨率、限制帧率、删特效或缩减音频的办法。

## 已观察到的代码开销

- `src/app/game-session.js` 的每次 `gameLoop` 都调用 `updateTimer` 和 `updateScore`；微信 renderer 中两者均直接 `draw()`，即使分数没有变化。同一次逻辑帧会发生至少两次全场景绘制。
- `ports/wechat/src/renderer.js` 的 `scheduleMotion` 另外使用 32/85 ms 定时器，可能与游戏循环重复绘制。点击和多个状态通知也直接重绘。
- DPR 最高为 3，全画面反复绘制使成本更高，但应首先去掉重复工作而非降低清晰度。
- 字号适配、文本测量、静态背景和按钮美术会参与重复绘制，适合按输入缓存。
- glitch 已限定选中的按钮、按 100 ms 缓存，不是全屏每帧像素处理；仍有像素读写与数组分配，需要单独测量后决定是否优化。
- 游戏开始后非游玩状态仍会继续申请 RAF；隐藏时已暂停音频和动效定时器，但主循环的调度还需要检查。不能简单停时钟，否则会破坏恢复与倒计时。
- BGM 已有双实例交叉淡化和暂停逻辑，25 ms 淡化定时器只在过渡时启用，暂不认定音频是发热主因。

## 执行顺序

### 0. 建立可比较的真机基线

Mac 连接 iPhone 后，固定设备、微信版本、构建、亮度和环境，避免充电状态不同影响比较。分别记录正常预览试玩和调试连接下的数据，不把 USB 充电/调试额外开销全算到游戏上。

场景：主页静置、普通局内、密集点击、换关、升级、结算、交换、glitch、切后台再返回。固定 seed 和操作时间线，记录每秒 draw 次数、每帧 CPU 时间 p50/p95、长帧、JS 分配/内存趋势，以及工具能提供的 CPU/GPU 指标。持续试玩 10–15 分钟比较发热与耗电；主观温感和设备可用的热状态分开记录。诊断计数应聚合采样，避免逐帧 console 输出干扰测量。

### 1. 合并重复绘制（优先）

优先在微信适配层把状态更新与最终绘制分开，同一次逻辑帧全部更新后只绘一次。保留原有逻辑更新频率和时钟语义。将动效绘制请求去重，不删除任何动画、不额外延迟按键反馈。点击命中矩形与交换遮挡判定不能依赖尚未执行的绘制结果；对这一点做专门回归。

完成后独立提交、测量；通过后再进行下一项。不要为了复用调度而先重构共享游戏规则。

### 2. 缓存不变的绘制输入

先缓存文本宽度、字号适配结果和稳定布局；按字体、文本、宽度和视口失效。再尝试缓存静态背景与稳定按钮底图，用相同 DPR 和相同混合顺序绘制；人物、呼吸、按下变暗、震动、交换和数字保持动态。控制离屏缓存总像素与数量，避免用大量内存换 CPU。截图出现锐度、边缘或色彩差异就不接受该缓存方案。

### 3. 清理闲置调度与分配

检查隐藏后 RAF、音频淡化及其他定时任务是否仍运行。仅在安全状态停调度，返回前台只恢复一次；保留“继续”弹层及等待玩家期间的计时暂停。保持主页/结算角色原有轻动效。

若剖析确认 glitch 成本明显，再复用像素缓冲、避免无意义的 surface 尺寸重设；不改变目标数、频率、持续时间、RGB 位移或切片结果。音频仅处理已证实的重复创建/无效调用，不改变声音表现。

## 不改坏的验收与回退

1. 同 seed、同输入时间线，对比每步游戏状态：分数、体力、挑战进度、连击期限、关卡、升级、随机目标和存档必须一致。
2. 固定动画时间点截图，对比主页/局内/升级/结算以及按下、交换中点、glitch、换关动画；另录制实际操作，确认节奏、音频、震动与触摸反馈不退步。
3. 重点覆盖交换轨道重叠时的双按钮保护、640 ms 时间补偿、入场不计时、快速连点、切后台恢复和多次重开。
4. 根项目 `npm run validate`、`npm run build`，小游戏 `npm run check`；共享文件如有改动，必须补 Web 回归。
5. 每项独立提交并保留前一版。若出现业务/视觉变化、触摸延迟、内存持续增长，或真机开销没有明确改善，则回退该项。发布前由用户复验体验。

第一阶段成功标准：每次逻辑帧不再重复全屏绘制，帧耗时或 CPU 开销在相同测试条件下下降，功能状态和画面表现一致。温度下降是待测结果，不用主观推测替代性能验收。

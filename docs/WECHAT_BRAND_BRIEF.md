## 2. 名称所对应的真实玩法

玩家每轮先阅读一条禁止条件，再观察按钮的颜色、形状、数字等属性，避开符合禁止条件的按钮，按完其余安全按钮。操作受倒计时约束，误按会产生惩罚；现有版本还包含连击、战斗、Boss、升级和干扰机制。

这里反复出现的体验是：**眼睛读到了提示，大脑需要完成判断，手指却已经准备行动。** 玩家既要及时操作，也要在按下前确认判断。

“手指等等我”把这一体验变成一句角色对白：可以理解为玩家对自己的手指说，也可以理解为大脑对手指说。名称中的“等等”强调判断与动作的配合；实际玩法仍按当前规则和倒计时运行。

## 3. 为什么选择“手指等等我”

### 3.1 用一句自然会说的话建立记忆

五个汉字组成完整的口语短句，方便在中文聊天中提及、转述和搜索。“我在玩手指等等我”能够直接说出口。`ThatButton` 保留为工程名，微信用户首先看到中文产品名。

### 3.2 让名字自带一个小场景

“等等我”隐含两个角色，以及“一个跑得快、一个在后面追”的关系。听到名字时，就可以想象一个急着按按钮的手指和一个努力跟上的大脑。这为头像、角色表情、海报构图提供了共同的故事起点。

### 3.3 把玩法中的矛盾变成轻松的幽默

名字对应“反应速度与正确判断”的拉扯。它允许玩家用轻松的方式描述一次误按，也为重试留出友好的情绪空间。用户明确希望少用负面语汇，因此品牌文案采用角色之间的调侃与配合，不贬低玩家。

### 3.4 给后续视觉留出空间

“大脑追手指”能够持续用于头像、开场插画或宣传画面，不依赖某一关的按钮排列。用户在选定名称时明确表示，海报和视觉形象已经有了画面感；随后又确认非常喜欢当前图标。

这些是本项目的设计取舍，不能据此推定点击率、传播效果或留存提升已经得到验证。

### 5.2 图像元素如何表达产品

| 元素 | 图中的表现 | 设计意图 |
|---|---|---|
| 大脑 | 粉色、圆润、伸手追赶，表情积极 | 代表观察与判断；让“我”有一个可见的角色 |
| 手指 | 白色卡通手套，食指朝按钮伸出 | 对应手机点击行为；表现“动作已经快一步” |
| 按钮 | 青绿色、带厚度、位于动作落点 | 明确这是一款围绕按键判断的游戏 |
| 角色关系 | 大脑在后，手指向前，辅以运动线 | 把“等等我”直接画出来 |
| 背景与轮廓 | 明亮黄色背景、深色粗轮廓、大色块 | 形成轻快印象，帮助小尺寸下区分角色轮廓 |
| 图标内无文字 | 用角色和动作承担表达 | 让有限空间优先服务图形识别，名称由平台文字区域展示 |

图标的视觉方向为明快、可爱、略带夸张的二维卡通。大脑和手指应保持清晰的独立轮廓。可爱的角色表达需要与游戏的判断挑战并存；当前定位仍是休闲益智与反应游戏。

图标适配时，应实际检查小尺寸显示、圆形与圆角裁切，尤其注意手指、脑部表情和按钮是否完整。生成时考虑过这些场景，但目前没有完整尺寸验收记录。

### 5.3 名称、图标与玩法应契合到什么程度

三者围绕同一个体验组织即可：名称提出“等等我”，图标展示大脑追赶手指，游戏让玩家在判断完成后再准确按键。

图标负责让人理解并记住角色关系。倒计时、连击、Boss、升级等系统可由游戏画面与介绍承接，头像不需要同时容纳所有机制。后续宣传图可沿用两个角色的互动，再配合具体玩法截图。

## 7. 开发者如何落实

### 7.1 先完成最小的名称一致性

当前微信端的主要绘制入口是 [`ports/wechat/src/renderer.js`](../ports/wechat/src/renderer.js)。核对时发现：

- `drawOverlay()` 的开始页仍显示 `THAT BUTTON` 与 `核心熔毁：那个键`。
- `drawBoard()` 的局内页头仍显示 `THAT BUTTON`。

下一步建议将微信端开始页与局内页头的产品名称统一为“手指等等我”。检查中文标题在窄屏下的宽度，并与分数、关卡等信息保持间距。已有玩法说明可继续承担规则教学。

修改应落在维护中的 `src/` 源文件，再重新构建。`ports/wechat/build/` 是生成目录，直接编辑其中的 `game.js` 会在下次构建时丢失。

### 7.2 接入图标时核对资源路径

当前构建脚本 [`ports/wechat/scripts/build.mjs`](../ports/wechat/scripts/build.mjs) 会生成入口、项目配置和音效，尚未将 `assets/branding/` 复制到运行包。

微信后台头像直接使用原图即可。若后续开始页或其他游戏画面需要读取这张图片，开发者还需补充资源复制与加载逻辑，并验证真机资源路径。

### 7.3 保持改名的工程边界

- 本次中文命名适用于微信版本；Web 版与阅星曈版各自的名称、界面安排继续按对应文档处理。
- 仓库名、模块路径、AppID、存档键和内部 API 标识应保持稳定；产品显示名单独管理。
- 图标中的角色故事用于表达现有体验。规则判断、误按惩罚、倒计时、连击和其他机制继续以现有实现及玩法验收为准。
- 共享玩法位于 `src/core/`、`src/config/` 和 `src/app/game-session.js`，微信适配位于 `ports/wechat/src/`。视觉调整优先在微信适配层完成。

### 7.4 按当前目标安排优先级

1. **先继续可玩验证：**名称和头像已可用于账号资料；恢复模拟器试玩，安排真机验证。
2. **完成必要的显示一致性：**替换微信端旧产品标题，核对简介与实际玩法。
3. **再细调视觉：**开始页插画、游戏内配色、角色反馈、宣传海报与分享图逐项设计。

用户明确希望快速完成创建，因此完整的视觉改版不应成为继续调试与验证的前置条件。

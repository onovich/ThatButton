# 研发路线与验收

形状维度仍是必需属性（圆、三角、方、星），仅移除颜色替代方案。当前原型已实现形状与数字条件的 AND/OR 真值表验证；设备实现应共享结构化条件并覆盖“仅形状成立、仅数字成立、都成立、都不成立”四种情况。移除“已试”这种不表达玩法结果的按键标签。

状态（2026-09-23）：本地 Lua 0.1.0 已实现当前数学练习原型并通过测试，见 [交付记录](DELIVERY.md)。下面完整游戏路线仍是后续规划，不代表本次全部实现。用户指定本地开发，Studio 只导入、校验和打包。

当前范围修订（2026-09-20）：用户已放弃纹理与 A–D 属性映射。设备端采用数学条件：multiple / ending / contains / odd / even / prime / composite；固定输入域 1–99。下文旧 Web 颜色条件对照仅保留为历史迁移思路，不作为当前设备版必做项。优先以 `design/number-rules.js` 的明确数学定义建立独立 fixture，覆盖 1 既非质数也非合数、2 为偶质数、平方合数、尾数与包含的差异、数字 0 参数。新增条件无需与 Web 旧颜色规则强行一一映射。复合条件及生产关卡生成仍待实现。

## 代码与工作目录

正式开发从已知提交创建 `codex/xteink` 独立 worktree；原目录保留 Web。先明确如何带入本轮未提交准备资料，README/封面单独收尾，不自动混入。每次命令显式 workdir，输出当前分支；不要只切 UI 标签后假定目录已变化。

建议结构：

```text
ports/xteink/
  app/index.lua             # 生命周期薄入口
  app/manifest.json        # 根据当前 Studio 模板生成，独立 app_id
  app/domain/rules.lua      # 结构化条件谓词，不引用 UI
  app/domain/game.lua       # 操作、护盾、回合、完成状态
  app/domain/view.lua       # 布局、触区、绘图
  app/domain/pixels.lua     # 数字、图形、反应堆符号
  app/domain/app.lua        # 输入路由、模式、刷新协调
  app/domain/guide.lua      # 隔离练习与手册
  levels/                  # 版本化确定性关卡和答案
  fixtures/                # Web 输出的语义对照样例
  scripts/generate.mjs     # 调用现有 JS 核心导出数据
  scripts/build.py         # 展开模块生成单 Lua 入口
  scripts/demo.py          # 浏览器输入驱动真实 Lua 回调
  tests/                   # 规则、宿主、输入、布局、恢复
  build/                   # 忽略的可重建产物
```

Web `src/` 是既有语义对照源，设备端不复制 DOM、Web Audio、墙钟循环和整个 create-app。首先离线导出确定性关卡，减少 Lua 随机数与 JS Math.imul/无符号溢出的差异；是否在线生成以后再决定。规则条件用 AST（group/shape/parity/number + and/or/not）或经验证的完整目录表达，固定 fixture 保留原 ruleId、seed、难度、按钮和 forbiddenIds。

## P0：平台与交付探针

复核 Pro 模板、Lua/API 版本、manifest ID 规则、字体、输入、刷新和预算。创建本项目专属 app_id，不能继承 RoyalTapestry 的 ID、工程或绑定假设。最小页含中文、1–9、四形、A–D、触摸、实体键、局刷请求、版本号和状态计数。

验收：本地构建 → Studio 导入后核实真正入口 → 校验/运行/导出 → 确认新下载文件的版本、大小、SHA256 → 当前设备 USB 盘身份核实后复制并校验 → 用户设备端安装及启动。各步单独记录。绝不沿用历史 E 盘推定今天的设备盘符，不将源码 ZIP 改名 .xtapp，不以推送窗口消失宣称安装成功。

退出重进与关机重启分别测计数恢复，确认 ctx.state 的实际落盘能力。若未确认，产品不承诺“自动保存”。平台故障先记录精确报错、模板版本和最小复现；Studio AI 回复按报告证据标注，不等同执行结果。无需为了应用开发重复烧录固件。

## P1：可验证单局

1. 从 Web 导出 fixture：全部 8 种常规规则＋兜底；单属性、且、或、非、奇偶与精确数字；2×2 / 2×3 / 3×3；不同种子及危险数边界。
2. Lua 判定与 JS forbiddenIds 对照。对映射后的每颗按钮验证危险/安全身份，至少一个安全键、一个危险键，重复提交幂等；生成不合格关卡立即报错。
3. 实现一局读条件→按键→误按→清盘→结算→重玩。没有墙钟消耗，错误清零连击；未处理安全键数从集合计算，不维护容易漂移的第二套答案。
4. 真实 Lua 宿主预览，而非重写一套 JS 游戏伪装设备模拟。明确本地字体替代、无真实残影；本地服务只监听 loopback，避免单线程空闲连接卡死曾遇到的问题。

退出条件：规则对照全通过，触摸和键盘完成同一局；操作不穿透弹层，重复/无效输入不重绘，全部触点在屏内且不重叠；构建入口在禁止动态 require 的宿主正常执行。

## P2：视觉与引导

从真实 Lua 回调输出开局、焦点、成功、误按、最长条件、菜单、规则、教学、教学完成和结算画面。检查 480×800 越界、字符裁切、禁用路径和触区。常用键目标 96px 以上，辅助目标至少 44×44；像素不是毫米，最终触摸舒适度靠硬件。

绘图硬上限按当前契约复核；先以历史 1024 为限，内部目标最多约 800 留出中文/引导余量。测最坏帧，不能只报首页。像素图按同色连续段合并矩形；不能为模拟透明遮罩耗尽预算。

测试首次跳过/重看、操作触发推进、错误保留指令、独立判断、教学入口禁用、退出恢复正式局与焦点。文字说明分页，不复制参考项目后期的滚动提示作为默认规则。

## P3：设备体验与轻量成长

用相同构建在真实设备验证连续触摸、实体键、长条件、20–30 次局刷后的残影与手动清屏，分别记录固件、app 版本、是否充电、观察和用户反馈。长时间思考无状态变化。局刷/全刷只承诺请求意图，实际刷新行为以设备为准。

单局通过再引入敌人 HP、整局攻击和静态升级，明确每个公式、连击跨回合边界和错误代价；时间升级删去或重新设计，不能混入 Web 原有分数榜。存档加 schemaVersion、catalogVersion、关卡 ID、已处理 ID、护盾和结果；加载校验，损坏安全回退，不把练习状态写进正式局。

## 发布检查与证据账本

每个版本记录 local commit/dirty、Lua hash、manifest version、Studio 入口一致性、平台校验、导出文件路径/hash、USB 复制、安装、启动、触摸、按键、刷新、退出恢复、断电恢复；未做的标“未验证”。平台修复回写本地后重测再发包。先建立能安装的最小版本，再扩大功能。

CI 应让 Web 的 validate/build 继续通过。设备检查使用单独命令与虚拟环境，依赖锁版本，不把本机参考 worktree 路径作为运行依赖。正式开发前为 Pages build/deploy 增加 main 分支条件，避免手动触发设备分支部署。准备阶段不修改发布工作流。

# 手指等等我：整体形象与 UI 重设计构想

版本：构想稿 v0.1 · 2026-09-28  
阅读对象：美术、动效、音效与前端开发  
落地重点：微信竖屏版本的完整游戏流程；角色与素材体系可供 Web 版本后续适配。

名称、简介和现有头像已经确定，详见[品牌说明](WECHAT_BRAND_BRIEF.md)。本文提出整款游戏的视觉与交互方向。角色延展、界面草图、色值和动效参数均为设计建议，尚未形成正式美术稿或实装效果。

## 一、先确定这款游戏给人的感觉

### 一句话定位

**一对性格互补的大脑与手指搭档，在一张充满弹性按钮的桌面上，完成紧张又好笑的判断挑战。**

玩家进入时觉得亲切，按下时觉得干脆，连对时觉得自己很机灵，失误后愿意和这两个家伙再试一次。

这次重设计的主线是：**把“我的手比脑子快了一点”变成角色之间的小喜剧，把“这次判断对了”做成清晰、利落的操作回报。**

### 从现有图标保留什么

<img src="../ports/wechat/assets/branding/shouzhi-dengdengwo-avatar-v1.png" alt="粉色大脑追赶白色手指，两位角色朝青绿色按钮行动，背景明黄" width="320" />

这张图吸引人的地方，在于它同时包含动作、关系和情绪：手指跃跃欲试，大脑努力跟上，两者都对眼前的挑战有兴趣。黄色背景让整个场面显得明亮，深色轮廓让角色和按钮显得结实、有劲。

因此，整款游戏应当持续兑现以下气质：

| 气质 | 玩家应该感受到什么 | 美术与交互如何表达 |
|---|---|---|
| 亲切 | 两位搭档和我一起过关 | 圆润角色、温暖表情、失误后的相互照应 |
| 机灵 | 看懂规则、点对按钮很有成就感 | 清晰的条件表达、利落的正确反馈、具体的结果回顾 |
| 轻快 | 点起来顺手，重来没有负担 | 短动画、清脆音色、直接的主要操作入口 |
| 好笑 | 小小的着急和手忙脚乱令人会心一笑 | 手指的冲劲、大脑的反应、两者之间的动作接续 |
| 有挑战 | 时间在走，我需要保持判断 | 清楚的倒计时、明确的扣减与进阶信息 |

“可爱”主要通过角色关系和动作表达。面向愿意接受判断挑战的玩家，人物可以天真、表演可以夸张，界面文字与规则仍然成熟、准确。

### 设计决策的三个判断题

1. 这一处设计能否让人联想到“大脑和手指是一对搭档”？
2. 玩家能否更快看清规则、判断按钮状态、确认刚才发生了什么？
3. 失误有明确结果，同时还保留了轻松重来的心情吗？

每个页面和新增效果都用这三个问题检查。只增加热闹、没有服务角色或操作的装饰，可以删去。

## 二、世界与角色：按钮桌上的双人喜剧

### 2.1 场景母题

建议以**“按钮小剧场”**组织整体形象：一张干净的桌面、一块可按压的按钮托盘、几张规则提示卡，以及在边缘互动的两位搭档。

桌面提供稳定的视觉舞台。关卡变化主要发生在按钮、提示和角色反应里。背景以大色面和少量局部图形维持气氛，局内的纹理与摆件密度要低。

这一母题可以自然连接全流程：

- 首页：手指已经凑到大按钮前，大脑伸手追上来。
- 开局：大脑把本轮提示递出来，手指收住动作，准备合作。
- 局内：按钮响应玩家，角色在边缘提供短促反应。
- 连击：两位搭档越来越合拍，动作从各自着急变成同步。
- 结算：桌面上留下这一局的成绩，两个角色给出对应反应。

### 2.2 角色性格与表演

| 角色 | 性格 | 典型动作 | 设计边界 |
|---|---|---|---|
| 粉色大脑 | 认真、灵活、努力把事情看清楚 | 抬眼读提示、伸手提醒、点头确认、开心击掌 | 保留大块脑纹与圆润轮廓；不将它塑造成迟钝或受嘲笑的一方 |
| 白色手指 | 热情、急性子、行动欲强 | 悬停、蓄势、点下、回弹、失误后摸头 | 保持卡通手套造型；食指动作明确，关节与其他手指简化 |
| 两者关系 | 会抢半拍，也会相互等一等 | 一前一后、眼神交流、同步前倾、通关后击掌 | 幽默来自配合过程；双方都值得玩家喜欢 |

第一阶段继续以“大脑”“手指”称呼角色，正式角色昵称可以以后决定。

### 2.3 最值得建立的标志动作

**手指悬在按钮上方，身体已经前倾；大脑一只手轻轻拉住它。看清之后，两者一起完成动作。**

它可以用作首页循环、开局过渡与宣传主画面的共同构图。原图中的“追赶”关系由此发展成可以持续表演的“搭档”关系。

局内角色不指向某个尚未判断的按钮，也不随安全答案改变表情。反馈只能在真实操作结果之后出现，避免角色泄露解题答案。

## 三、整套视觉语言

### 3.1 轮廓、材质与空间

- **轮廓：**深海军蓝描边，转折圆润，曲线简洁；重点角色比普通面板更有轮廓重量。
- **材质：**二维卡通为基础，用一层明确的侧面和小块高光表现按钮厚度。角色阴影控制在少量色阶。
- **空间：**界面保持正面阅读。首页插画可有斜向冲势，局内棋盘的基准排列保持稳定。
- **形状：**按钮是整套界面的主形状，规则卡是信息容器，角色是情绪焦点。三者的外形职责清楚。
- **装饰：**速度线、小星点、短弧线集中在事件发生处；文字区域和规则区保持干净。

当前的黑底、荧光绿、扫描线、系统告警和英文终端标题，应逐步替换为这套明亮的桌面与角色语言。

### 3.2 建议品牌色板

以下是给第一轮设计稿使用的起始值，并非对原图颜色的精确采样。

| Token | 建议色值 | 用途 |
|---|---|---|
| `ink` | `#111B44` | 文字、描边、图标轮廓 |
| `sun` | `#FFE249` | 首页主背景、品牌大色面、重要庆祝 |
| `brain` | `#FF8CB0` | 大脑角色、温暖的辅助强调 |
| `button` | `#28D4CD` | 首页主按钮、主要操作、正向反馈装饰 |
| `paper` | `#FFFEF7` | 局内阅读底、规则卡、内容面板 |
| `alert` | `#F0644E` | 时间紧迫、实际扣减和错误反馈 |

首页让黄色充分出场。局内以浅色阅读面和稳定的深色文字为主，将黄色收至边缘或局部，让棋盘属性色容易辨认。文字默认使用 `ink`；按钮上的文字也优先用深色。

实色配对计算中，`ink` 在上述五种底色上的对比度约为 5.25:1 至 16.43:1。描边、阴影、透明度和实际字号仍需在设计稿与真机中复核。

### 3.3 品牌色与解题颜色分别管理

棋盘颜色是题目条件的一部分，当前包含红、蓝、黄、紫。前端应保留这些属性 ID 和语义，将它们管理为独立的 `board.*` 色板。

- 品牌青绿色用于主操作等区域，不把所有可点的题目按钮都改成青绿色。
- 红色题目按钮保持“红色”属性，不被默认画成错误或危险状态。
- 安全与禁按不能预先用颜色、发光、脸部表情或形状大小区分。
- 状态通过按下深度、记号、轮廓和文字共同表达。必要时研究色名辅助显示，避免只依赖色觉辨认。

### 3.4 字体与尺寸层级

| 角色 | 建议处理 | 390 宽设计稿的起始尺寸 |
|---|---|---|
| 产品标题 | 原创中文标题字，继承角色的圆润粗轮廓；允许少量错位与倾斜 | 34–40 |
| 规则正文 | 清晰的系统中文黑体，中粗；逻辑词、数字与否定词完整可读 | 20–24 |
| 按钮内数字 | 稳定、易区分的数字字形，重点检查 1/7、6/9 | 18–22 |
| 主要操作 | 系统中文黑体，加粗 | 18–20 |
| 状态与结果标签 | 系统中文黑体，稳定基线 | 14–16 |

标题字只承担品牌展示。规则正文不做倾斜、跳动、渐变填字或复杂描边。英文缩写可在开发日志中继续使用，面向玩家的主信息优先用中文。

### 3.5 间距、圆角与触感

布局以 4 为基本间距单位，常用 8、12、16、20、24。面板、按钮和角色轮廓使用有层级的圆角：大托盘约 24，规则卡约 16–20，题目按钮约 14–18，数字小标签更紧凑。

主要按钮使用一层清楚的厚度，按下时顶面下降、侧面变薄，再快速回弹。面板本身保持稳定，避免整屏同时起伏。

## 四、游戏过程中的情绪节奏

| 时刻 | 玩家主要任务 | 情绪与表演安排 |
|---|---|---|
| 打开游戏 | 理解这是怎样的游戏，并开始 | 展示完整的角色关系与一个明显的开始按钮 |
| 看本轮规则 | 阅读并建立判断 | 大脑的小动作收束，规则卡成为视觉中心 |
| 连续点击 | 判断与操作 | 点击反馈短、清楚，角色处于外围 |
| 连击形成 | 保持节奏 | 两个角色同步一下，连击数与实际收益明确显示 |
| 剩余时间变少 | 把注意力收回题目 | 时间区加强提示，减少其他表演 |
| 一轮清完 | 确认结果，准备下一轮 | 角色短暂击掌，随后尽快让出新提示 |
| 挑战结束 | 知道原因，决定是否重来 | 先交代事实，再给温暖的角色反应和重试入口 |

表演的原则是：**需要思考时收束，结果发生时释放。** 游戏的喜剧感来自恰当的时机。

## 五、全流程页面构想

### 5.1 首页：第一眼就能认出图标里的游戏

背景为品牌黄。中文标题位于上方，两位角色围绕一个大的青绿色按钮形成构图。大按钮本身就是“开始游戏”的操作入口；角色、投影和点缀不遮挡文字与点击区域。

```text
┌─────────────────────────┐
│      安全区与平台胶囊避让      │
│                         │
│       手指等等我          │
│    大脑追上来，手指悬停      │
│                         │
│       ╭────────╮        │
│       │ 开始游戏 │        │
│       ╰────────╯        │
│  读懂提示，点完安全按钮。    │
│                         │
│   最高第 12 关 · 1280 分   │
└─────────────────────────┘
```

保留一个主要入口和已有最高记录。图中的成绩为排版示例，实装读取本地真实记录。首屏不增加尚未实现的货币、商城、排行榜或任务入口。

### 5.2 首次理解规则：融入现有开局

第一版沿用现有开始流程，用一句规则说明和第一轮的小棋盘完成理解。角色可以在入口旁提示“先看清，再点准”。

以后如制作可操作教学，应使用独立示例题，并明确区分练习与正式计分。给正式局额外阅读时间、强制等待或暂停倒计时，都涉及流程变化，需要另行确定。

### 5.3 主游戏页：规则、按钮和时间构成核心

主要阅读顺序为：**规则 → 棋盘 → 时间 → 体力与对手 → 连击与成绩。** 时间靠近棋盘上缘，玩家点击时能顺带看到它。

```text
┌─────────────────────────┐
│ 第 6 关          320 分   │
│                         │
│  脑  本轮别按             │
│  ╭───────────────────╮  │
│  │ 红色且数字为奇数的按钮 │  │
│  ╰───────────────────╯  │
│  时间 ━━━━━━━━━  8.4 秒  │
│                         │
│   [红 △ 03] [蓝 ○ 08] ...│
│   [紫 □ 12] [黄 ☆ 05] ...│
│   [蓝 △ 02] [红 ○ 10] ...│
│                         │
│       还剩 4 个安全按钮     │
│  体力 82/100  连击 4      │
│  连击剩余时间小环 · 威力 +3 │
│  考官   耐力 180/500      │
│         反击 18           │
└─────────────────────────┘
```

以上数字与题目只是布局占位。正式规则须直接使用核心给出的规则内容，显示数值须来自当前状态。

**规则卡：**大脑只在左上角留小头像或探头，气泡式边缘可以建立“它正在提醒我”的感觉。规则文本保持固定基线，长规则优先增行，完整保留“且、或、不是”等逻辑关系。不得把现有文本强行截成两行。

**棋盘：**统一按钮底座与深色信息。形状、数字、颜色都有固定位置与明确层级。已正确按下的按钮呈现下沉和完成记号，并保留原属性，便于玩家回看。

**倒计时：**使用连续缩短的时间条和秒数。紧迫时只加强时间区与必要反馈，不让所有按钮一起变成警报红。

**状态区：**体力、对手耐力和反击值清楚可查；连击旁用小环或短条表示连击有效时间，避免与本轮总倒计时混淆。

**短屏：**先减少角色占用与装饰，再压缩间距和次级信息排布。棋盘和本轮规则保持同屏；局内不引入纵向滚动。

### 5.4 过轮与击败对手

每轮清空安全按钮时，做一次短促的整齐落定：已按下的按钮稳定，搭档完成小击掌，实际伤害数字落到对手区域。

只有核心返回击败对手时，才进入更完整的庆祝与升级选择。两种事件在视觉强度上要有差异，玩家能够感受到“清完一轮”与“完成一个对手挑战”的层级。

### 5.5 升级选择：两位搭档一起挑一件小帮手

沿用当前升级选择流程，桌面上排列三张竖向选择卡。每张卡由小插画、易懂名称和准确的效果说明组成，整张卡可点。

建议的名称示例：

| 现有升级 ID | 建议展示名 | 必须保留的实际含义 |
|---|---|---|
| `chain-span-plus` | 多留一拍 | 连击有效时间增加；当前基础配置为 500 ms |
| `max-hp-plus` | 精神满满 | 体力上限增加；当前基础配置为 24，恢复效果按核心结果展示 |
| `round-time-plus` | 再想一会儿 | 每轮时间增加；当前基础配置为 1200 ms |
| `base-attack-plus` | 配合有力 | 基础攻击增加；当前基础配置为 4 |
| `combo-reward-plus` | 越来越合拍 | 增加连击收益，具体效果读取现有升级逻辑 |

这些名称是候选文案。实装将毫秒换算成秒，例如“每轮时间 +1.2 秒”，并使用实时配置值。插画可以采用节拍器、软垫、时钟等小道具，但不能暗示额外消费或虚构效果。

### 5.6 结束与回顾：明确原因，轻松再来

结算页用浅色大面板承载成绩，角色在上方形成一组小表演。误按耗尽体力时，手指收住、大脑扶它一下；时间耗尽时，两者一起看向停住的时钟。

标题可用“这次到这里”，原因直接写“体力耗尽”或“时间到了”。有条件时展示最后的规则、误按按钮或剩余安全按钮，帮助玩家理解这一局。

```text
┌─────────────────────────┐
│       两位搭档的结束动作     │
│        这次到这里          │
│        体力耗尽            │
│                         │
│     第 12 关 · 1280 分     │
│     最高纪录：第 15 关      │
│                         │
│  最后规则：……             │
│  最后误按：[按钮原属性]      │
│                         │
│      [  再来一局  ]        │
└─────────────────────────┘
```

原因读取 `failureReason`、体力和回顾数据。存在对手反击导致体力耗尽的情形，不能将所有非超时结束都解释为“按错了”。没有相应回顾数据时省略该行，不补写一个猜测原因。

“再来一局”应映射到真实的重新开局行为。不得把同一个入口标成“继续本关”或“复活”，造成流程误解。

### 5.7 加载、切后台与设置

- **资源加载：**使用小型搭档图形和明确状态；加载失败给出可执行的重试说明。原有基础绘制应能作为图片未就绪时的回退。
- **切后台：**沿用当前暂停时间计算的机制。返回后的具体继续方式以实现为准；若增加“点击继续”，前端必须补充真实暂停状态与输入门控。
- **设置：**音效、震动、减少装饰动画属于后续可选功能，需有实际状态控制后再展示入口。
- **分享图：**可以沿用搭档与成绩构图制作宣传模板；本构想不将分享或邀请设为继续游戏的条件。

## 六、让现有战斗系统融入新形象

现有版本包含玩家体力、对手耐力、反击、连击、升级和干扰。它们应在新的角色语言中找到位置，数值含义仍需清楚。

| 现有系统 | 建议视觉表达 | 前端需要遵守的对应关系 |
|---|---|---|
| 玩家 HP | 两位搭档共用的体力条，心形仅作标识 | 保留实际 `hp/maxHp`，避免把 100 点体力误画成固定三次失误机会 |
| 对手/Boss | 圆润的“按钮考官”或机关角色，位于状态区 | 保留对手耐力与反击信息，不能伪装成只涨不跌的普通进度条 |
| 清轮造成伤害 | 搭档动作收束，考官弹性后退一下 | 使用 `showBossHit` 的实际结果，不在每次安全点击时虚构对手掉血 |
| 连击 | 两位角色短暂同步，小环显示接续时间 | 使用真实连击数、窗口与收益；不新增没有计算依据的“默契百分比” |
| 移动按钮 | 按钮底座出现小弹簧或短腿，按真实偏移移动 | 绘制与命中区域使用同一位移，保持原有触发与持续时间 |
| 视觉干扰 | 风线、轻薄纸带等局部表现候选 | 读取原有阶段与强度；验收不能遮蔽必要题目信息或额外改变难度 |
| 升级 | 搭档的小道具与准确效果卡 | 保留升级 ID、选择规则、数值和持续范围 |

“按钮考官”是新增美术方向建议，角色名与外观尚未定稿。可以用一套基础轮廓加少量配件区分当前不同对手，逐步扩展。大脑与手指仍是最主要的品牌角色。

特别注意：当前连击状态中保留了一些历史倍率字段。展示文案应依据实际生效的 `streak/chainCount`、`damageBonus` 等数据，不能直接把旧倍率标签当成新的得分承诺。

## 七、反馈、动效与声音

### 7.1 反馈时长建议

以下是第一轮打样的起点，最终以连续点击的手感与真机性能调整。

| 事件 | 动作与画面 | 建议时长与约束 |
|---|---|---|
| 按钮接收点击 | 顶面下沉，阴影缩短 | 立即响应，约 50–80 ms |
| 正确点击 | 小幅回弹后落入完成态，局部亮点 | 约 100–160 ms；不延迟后续输入 |
| 误按但未结束 | 当前按钮短摆，显示实际体力扣减；手指收一下 | 约 160–240 ms；其他按钮保持可判断 |
| 连击形成 | 两位角色一次同步，小数字轻弹 | 约 180–260 ms；高频事件合并，避免堆满文字 |
| 清完一轮 | 托盘局部落定、短击掌 | 约 220–320 ms；不额外拖长已存在的过轮等待 |
| 击败对手 | 考官让位、搭档庆祝，进入升级 | 约 350–500 ms，尊重实际流程边界 |
| 倒计时紧迫 | 时间条边缘与秒数有限强调 | 控制在时间区；装饰动画优先减少 |
| 结束面板出现 | 面板轻落，角色反应随后补上 | 约 220–320 ms，主要重试入口尽快可用 |

减少动画时，保留按下状态、数值变化和规则必要运动，关闭纯装饰弹跳、粒子与大幅镜头运动。移动按钮若属于关卡机制，不能被一个视觉设置悄悄取消。

### 7.2 声音的形象

按钮声音建议向短促的“啵、嗒、咔”靠拢，带一点软质玩具与机械触点的结合。连击使用有限的音高变化，让节奏逐步明亮；错误反馈短且明确，结算音乐保持克制。

所有重要事件同步有视觉反馈，静音也能完整理解。已有微信音频适配位于 `ports/wechat/src/audio.js`，后续替换资源时保留相应事件职责。

### 7.3 文案语气

| 场景 | 建议表达 |
|---|---|
| 开始 | 开始游戏 |
| 本轮规则前缀 | 本轮别按 |
| 连击 | 连击 4；收益另显示实际数值 |
| 清完安全按钮 | 全部点对了 |
| 一次误按 | 按错了，体力 −18（数值按实际结果） |
| 超时 | 时间到了 |
| 体力耗尽 | 体力耗尽 |
| 新纪录 | 新纪录！ |
| 重开 | 再来一局 |

“手指，等等我”“这次配合上了”等角色对白适合放在短暂过渡或宣传里。判定、扣减与结束原因使用直接语言；幽默不要覆盖事实。

## 八、美术交付建议

### 8.1 第一轮优先做出的画面

先完成三张能够验证整套气质的设计稿：

1. **首页：**标题、两位角色、主按钮和最高记录组成完整构图。
2. **复杂局内页：**3×3 棋盘、长规则、倒计时、体力、对手、连击同时存在。
3. **结束页：**成绩、明确原因、一次具体回顾和重试入口。

三张稿应当使用同一套轮廓、按钮厚度、字级和间距语言。局内页先拿真实题目验证，避免只用短占位文案掩盖空间问题。

### 8.2 资源清单

| 资源 | 首批内容 | 交付形式 |
|---|---|---|
| 中文标题 | 标准横排、首页组合版 | 可编辑矢量源文件与透明 PNG |
| 大脑角色 | 待机、读提示、提醒、肯定、结束反应 | 独立角色图层、统一基准与锚点 |
| 手指角色 | 悬停、按下、回弹、收手、击掌 | 同一套比例、清楚的动作落点 |
| 双角色组合 | 首页追赶、同步、庆祝、互相照应 | 保留分层，方便动效复用 |
| 按钮体系 | 默认、按下、完成、错误反馈；2×2 至 3×3 排列 | 结构尺寸说明，状态对照图 |
| 规则与状态组件 | 规则卡、时间条、体力、对手耐力、连击小环 | 标明伸缩区域、文字与图形边界 |
| 升级图标 | 与五种现有升级对应的小道具 | 统一视角与描边的独立图标 |
| 对手角色 | 一套考官基础形象，优先支持待机/受击/让位 | 可拓展配件结构，避免首批资源过量 |
| 小型特效 | 运动线、点状亮点、短星形反馈 | 单独透明素材或绘制参数 |

现有头像作为形象参照和账号素材完整保留。角色动作图需重新整理形体与遮挡关系，不能假设从单张合成头像中直接裁切就能得到可用的全套角色。

### 8.3 面向前端的导出约定

- 位图优先透明 PNG；明确源文件、导出文件与实际使用尺寸。
- 角色参考导出可从 256、512 像素级别开始，按实际显示大小和设备像素比复核。
- 标明角色脚底基线、接触点、动画锚点和允许裁切范围。
- UI 面板交付伸缩规则，避免将整块页面输出成一张无法响应布局的图片。
- 数字、规则与运行数据由前端绘制。装饰字只用于固定标题。
- 正式素材进入 `ports/wechat/assets/` 并纳入版本管理；构建产物由脚本生成。
- 交付包带一张资源清单，说明文件名、用途、状态和版本；需要字体文件时同步提供使用范围说明。

## 九、前端实现建议

### 9.1 先按当前 Canvas 工程组织

当前微信版本通过 Canvas 绘制，没有现成的 DOM 页面组件。建议在 `ports/wechat/src/` 内逐步形成以下职责：

```text
theme / tokens       色板、字级、间距、轮廓和厚度
layout               安全区、规则卡、棋盘、状态区与弹层几何
copy                 微信版标题、中文标签、候选角色对白
assets               角色图片、图标的加载与回退
feedback             纯视觉反馈、事件合并与动画生命周期
renderer             将真实会话状态组织成画面与命中区域
```

这是建议的职责划分，文件数量可以按实现需要决定。共享规则、数值和存档逻辑继续由现有核心维护。

### 9.2 源码对照

| 入口 | 当前作用 | 改版时重点 |
|---|---|---|
| [`ports/wechat/src/renderer.js`](../ports/wechat/src/renderer.js) | 首页、棋盘、升级、结束页、反馈与命中区域 | 重建视觉层级与布局，按事实渲染反馈 |
| [`ports/wechat/src/game.js`](../ports/wechat/src/game.js) | Canvas 创建、触摸、存储、前后台时钟 | 保持输入与时间逻辑一致；按需要衔接资源与绘制循环 |
| [`ports/wechat/src/audio.js`](../ports/wechat/src/audio.js) | 点击、连击、错误、升级等声音 | 替换声音形象，保留事件对应关系 |
| [`ports/wechat/scripts/build.mjs`](../ports/wechat/scripts/build.mjs) | JS 打包、配置和音效生成 | 增加正式美术资源复制与校验 |
| [`src/app/game-session.js`](../src/app/game-session.js) | 共享游戏流程与渲染事件 | 作为状态来源，避免在视觉层另造判定 |
| [`src/core/recap.js`](../src/core/recap.js) | 原因、按钮、规则、成绩回顾 | 为准确的结束页提供已有事实 |

当前构建脚本还不会复制品牌图标；当前 `sourceElement` 在 Canvas 点击路径中也不能视为一个可直接读取位置的 DOM 节点。若需要按钮原位粒子或摆动，需明确传递按钮 ID/坐标，或在微信适配层建立可靠映射。

### 9.3 布局与绘制约束

- 以 390×844 作为第一轮设计基准，同时检查 360 宽、430 宽与 320×568 的紧凑场景。数值均为设计逻辑单位，不直接等同于导出图片像素。
- 安全区与平台胶囊按实际宿主信息避让，关键文字和操作不进入被遮挡区域。
- 题目按钮的短边目标为 56 逻辑单位以上，普通操作目标至少 44。小屏先收缩装饰，再调整几何。
- 长规则完整显示，棋盘保持同屏。宽度、行数与字号共同适配，不能依赖截断来凑版面。
- 所有移动、缩放后的视觉按钮和命中区域保持一致；相邻点击区域不能含糊重叠。
- 升级与结束面板出现时，底层棋盘不能继续接收点击。
- 纯装饰动画使用受控的帧更新与事件状态，避免每次重绘重复启动动画或叠加计时器。
- 以真实会话时钟决定游戏状态；动画播放不重置倒计时、不制造额外反应时间。
- 静态图片与布局结果可以缓存。新增图形 API、图片加载和动画能力后，同步完善现有模拟 wx 测试替身。

### 9.4 语义不能悄悄变化

1. 颜色、形状、数字条件及其组合保持一致。
2. 误按扣减、时间耗尽、对手反击与结束原因各自准确。
3. 连击数、有效窗口和收益沿用核心事实。
4. 移动与干扰的时间、对象和强度不因换皮被重写。
5. 存档键、AppID、升级 ID 与内部 API 标识保持稳定。
6. 新的教学等待、手动暂停、复活或其他流程若要加入，独立说明和确认。

## 十、实施顺序与验收

### 第一阶段：对齐一组完整的设计稿

美术提交首页、复杂局内页和结束页；前端同步用真实规则与状态检查布局。评审重点是三张图能否让人认出同一款游戏，以及复杂局内页是否仍然清楚。

### 第二阶段：做出可连续游玩的视觉切片

实现首页 → 一轮操作 → 正误反馈 → 结束重开的连贯流程，再接入升级、对手和干扰表现。角色动作数量先控制在能体现搭档关系的范围内。

### 第三阶段：补齐完整状态与设备验证

补齐资源加载、长规则、短屏、不同棋盘、后台切换、升级选择、连击到期、实际结束原因等状态，完成手机验证后再扩展更多角色动作和宣传素材。

### 交付核对

- [ ] 从头像、首页到局内、结算，角色比例、线条与颜色语言一致。
- [ ] 玩家第一眼能找到开始入口，开局后能找到规则、棋盘和时间。
- [ ] 复杂规则、四种题目属性色、数字与形状均可清楚辨认。
- [ ] 角色与特效没有提前透露安全答案，也没有遮挡判断内容。
- [ ] 点击、扣减、连击、清轮和击败对手的反馈层级清楚。
- [ ] 结束原因与真实状态一致，重试入口行为与文字一致。
- [ ] 紧凑屏幕没有截断关键规则或强迫局内滚动。
- [ ] 连续多局、切后台和静音场景可正常完成。
- [ ] 玩法验证沿用现有可重复检查，新增视觉相关断言只覆盖真实交互风险。
- [ ] 设计稿、导出素材、资源清单与实际实现保持可追溯。

## 十一、给美术与前端的共同工作目标

先把首页、一个信息完整的 3×3 局内场景、一次有具体原因的结算做成同一款游戏。让两位搭档的关系可见，让按键手感与判断结果清楚。

当这三处形成统一体验，再扩展更多动作、对手与宣传画面。整个方案最终要兑现名字和图标带来的期待：**明亮、机灵，有一点点着急；点对的时候痛快，失误之后还想和这两个家伙再来一局。**

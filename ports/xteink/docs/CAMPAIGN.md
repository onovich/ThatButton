# 0.3.0 · 40关连续挑战

## 本轮节奏与时长估算

用户选择单轮20–30分钟。设备版设40关固定终点，题目动态生成，没有Boss或敌人战。0.4.0起加入逐关倒计时，详见COUNTDOWN.md。

- 1–10关：预计每关15–25秒，共约2.5–4分钟。
- 11–30关：预计每关30–45秒，共约10–15分钟。
- 31–40关：预计每关40–60秒，共约7–10分钟。
- 合计约20–29分钟（含读条件、选择及结算推进）。这是假设性的首次游玩预算，不是实测；熟练玩家可能更快，重试会更久。

保留原版盘面与基础逻辑难度分段；最后10关额外引入质数/合数。稀有槽位由种子奇偶决定，为32/35/38或33/36/39。最多3/40关（7.5%），互不相邻，前30关绝不出现；若盘面不满足危险数量要求则回退普通精确数字题。稀有题只用单个数字条件，不再叠加形状AND、NOT或OR。练习模式允许主动选质数/合数，不受挑战出题频率限制。

数字文案直接写“质数”“合数”“3的倍数”“尾数为7”；保留形状和“以及”“或”“除了……之外”。结果页沿用已批准的生图设计并由真实Lua渲染，最终通关页在0.3.1中增加独立40奖章，保持成功页的排版层次；设计见design/concepts/VICTORY.md。

状态带generation=3标记，避免旧版本已按集合套到新的题目上。0.2.0的未完成挑战会从第一关重新开始；0.3.0内部可恢复关卡、失败和最终通关状态。

## 原版究竟有多少关

原版 src/core/level.js 每关随机生成，src/app/create-app.js 的 levelComplete / continueAfterUpgrade 持续递增 level。没有固定关卡目录或最终关。src/config/difficulty.js 包含五段：1–2、3–5、6–10、11–15、16及以后；对应2×2、2×3、3×3、3×3、3×3。src/config/encounters.js 的四种敌人身份之后继续 DEEP LOOP，不能算成四关。

旧设备版本只有固定练习面板；“0关”只描述其未实现进度，不描述原版。这一遗漏在本次补上。

## 已迁移与适配

- scripts/export-progression.mjs 直接导入原版 difficulty/battle 配置，输出 domain/progression.lua；每次本地 build 自动重新导出。不是另写一份未经对照的难度表。
- 迁移随机盘面、数字不重复、形状维度、危险数范围、按完全部安全键过关、已按键不可重复计分、每个安全键10分、初始生命100、误按扣18、耗尽失败、清盘后推进。
- 原版颜色规则按已确认的设备方案替换为数学谓词，保留单条件、AND、NOT、OR的难度层次。颜色OR替换为两个数字条件OR；颜色NOT与形状AND替换为形状AND非数字条件。精确数字有有界重试后的兜底。生成结果不声称与原版相同seed的彩色答案集合等价。
- 原版 compoundExact 只有一个危险键，而允许该模板的高难度段最低危险数为2；沿用其筛选逻辑时通常不会入选，精确条件保留为兜底，不宣称所有模板均正常出题。
- 使用确定性的 Park–Miller RNG。第一次种子20260923，失败重开或最终通关后再来一轮更新种子。同关重试沿用原题并恢复本关开局生命/分数，不能重复刷分。
- 0.4.0已接入设备逐关倒计时，不运行原版移动干扰、墙钟连击；敌人HP/升级系统本次未迁移。这里迁移的是关卡与结果闭环，不是原版战斗系统全部功能。

## 结果页面

设计参考 design/concepts/results-v1-original.png，由内置 imagegen 生成，提示词同目录。最终页面由真实Lua绘图实现：大标题、勾/叉结果图形、得分区、主按钮与次按钮。

- 第1–39关清盘：本关完成、本关得分、下一关、再玩本关。
- 第40关清盘：全部通关、累计得分、再来一轮、再玩本关；不生成第41关。
- 生命耗尽：挑战结束、累计得分、重新开始、重试本关。
- 不会每次安全/危险点击都插入解释段落；主界面只有已按状态及生命数变化。
- Back进入独立练习设置，试练条件使用旧固定样例；返回挑战恢复原进度，修改练习不会修改挑战题目。
- 挑战存入ctx.state，加载时重新生成题目核对已按集合、分数、生命及结果状态。正常重入已测；断电存档仍需真机核验。

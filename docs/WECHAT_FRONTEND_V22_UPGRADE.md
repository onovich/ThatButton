# 微信小游戏升级页 v22：文案与视觉复核

> 此版的升级页主体仍由 Canvas 绘制，后续已在 [v23 原画切图验收](WECHAT_FRONTEND_V23_UPGRADE_ART.md) 中按用户模拟器截图修订。本文保留设计探索和文案决策记录。

日期：2026-09-30

## 现有升级

小游戏的候选池有 **4 种**，每次随机展示 3 张卡；可重复获得，效果累计。第五种 `combo-reward-plus` 仍保留在 Web 原版的公共定义中，小游戏已过滤它。

| 小游戏显示文案 | 每次选择的实际效果 | 内部 ID |
| --- | --- | --- |
| 连击接续更久：接续时间 +0.5 秒 | 连击窗口 +500 ms | `chain-span-plus` |
| 体力上限提升：上限 +24，当前体力 +24 | 最大体力和当前体力都 +24 | `max-hp-plus` |
| 每轮时间更长：时间上限 +1.2 秒 | 每轮计时上限 +1200 ms | `round-time-plus` |
| 清轮进度加成：每次清轮，挑战进度额外 +4 | 每轮清空按钮的基础挑战进度 +4 | `base-attack-plus` |

删除了小游戏卡面上容易被误解为提高难度的“挑战再加速”等旧表述；卡名与副文案均说明玩家得到什么。底层数值与 Web 逻辑没有改动。

## 原画核对与新版设计

原画负责人交付过 [v15 升级整页原画](../ports/wechat/assets/concepts/2026-09-29/v15-art-polish/upgrade-v15-choices-abc-390x844.png)。此前 Canvas 页面已按该图实现了暖白背景、细描边标题和三张简洁卡片。它与首页、局内、结算的黄色舞台及更饱满的漫画字标题相比，视觉确实割裂；问题主要来自 v15 原画，而不是缺少原画或漏接资源。

本次先以现有升级页、局内和结算画面为参考，用内置 `image_gen` 生成 [整页风格稿](../ports/wechat/assets/concepts/2026-09-30/upgrade-v22/upgrade-fullscreen-study.png)，再从同一方向生成透明的 [“挑战完成！”标题母图](../ports/wechat/assets/concepts/2026-09-30/upgrade-v22/title-upgrade-transparent-master.png)。布局及卡片以 Canvas 确定性绘制，角色仍使用已验收的 v11 `running-pair` 原画，未采用风格稿中重新绘制的角色。

整页设计提示词摘要：以当前升级页为编辑目标，以已验收的游戏和结算页为风格参考；设计 390×844 竖屏升级选择页，黄色云朵舞台、深海军蓝粗描边、青绿底部叶丛、奶油白实体卡片与对应能力颜色；保留三卡选择、分数与体力，卡面字可读，角色与 v11 造型一致。标题资产提示词摘要：在上述整页设计中单独提取“挑战完成！”的白色漫画美术字，深蓝粗描边、轻微黄色投影，透明背景，无其他元素。

运行时使用压缩后的 [透明标题图](../ports/wechat/assets/runtime/title-upgrade-v22.png)，900×336，约 103 KB。其余背景、角色复用现有已验收资源。窄屏与常规屏都重新排版，卡片保留可点击范围与选择动效。

## 按钮移动机制核对

共享核心有 `moving_button` 机制：从 **第 19 关的第 2 次挑战** 起解锁，随机选 2 个非禁用按钮，在短暂预备后约 2.6 秒内于原位置附近晃动，水平和垂直位移最多各 6 px。按钮身份、规则与安全属性不变；小游戏绘制区域和点击区域使用相同的位移。第 2 关本身不会触发该机制。

此外，换新关的按钮采用逐个缩小离场、逐个过冲入场的动画；按错按钮会短暂左右晃动。这些是视觉反馈，不是关卡机制。若玩家看到的是第 2 关持续晃动，须根据关数与录屏再复现，因为配置不允许该处出现 `moving_button`。

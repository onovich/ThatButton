# 微信小游戏角色动画回退

日期：2026-09-30。用户认为 v19 新姿态序列帧不自然、角色不一致，决定暂停该方案，恢复先前基于已验收 v11 静态原图的轻微抖动动画。

## 当前运行方式

- 首页使用 `running-pair.png` 单张原图，按 8 个刚体位移／轻旋转状态以 12 fps 循环。
- 局内使用 `separated-pair.png` 单张原图，按透明空隙分成左右两半，让两位角色以错峰小幅上下浮动循环。换关时延续原动画时钟，不重新登场。
- 结算使用 `caring-pair.png` 单张原图，在 300ms 稳定后，以 6 个极小位移／缩放状态轻呼吸；扶头接触和五官始终来自同一张原图。
- `game.js` 不再加载 v19 新姿态图，`build.mjs` 不再打包它们，并清理已有构建中的旧帧目录。源图与运行时导出仍保留在版本化素材目录以供日后复核，不作为当前游戏资源。

这次回退只涉及角色动画素材与绘制。v19 的分数对齐、按钮按下变暗、状态图标呼吸、旧按钮退场／新按钮入场、入场期间停表均保留。

## 检查

- 运行时 Canvas 截图：`ports/wechat/tests/visual-evidence/v20rollback-{home,game}-motion-t300-390-safe47.png` 与对应 `t470`，以及结算 `t650`／`t850`。三个场景均只显示原 v11 角色造型，没有跨帧五官或描边变化。
- `ports/wechat` 的 `npm run check`、根项目的 `npm run validate` 和 `npm run build`、v11 基准哈希检查均通过。
- 构建目录 `build/art/frames` 已移除，构建后的 `game.js` 不含 `art/frames/` 引用。

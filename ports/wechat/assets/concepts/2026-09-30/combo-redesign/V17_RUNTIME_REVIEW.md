# v17 运行图与连击设计终审

对照 2026-09-30 的运行时整屏图与本目录的原画叠加稿，**建议以 v17 运行时的透明 COMBO! 字标为最终视觉方向**。它比可编辑 HTML 样稿更醒目，黄色立体字、深蓝主边与细白外边贴近已签收三屏原画；动态数字也比旧版“4 连击／接续 2.1 秒”的两行小字清楚。不要再把旧奶油色胶囊或提示文字放回顶部。

运行图：[320／4 连击](../../../../tests/visual-evidence/v17-game-320-safe46.png)、[320／12 连击](../../../../tests/visual-evidence/v17-game-combo12-320-safe46.png)、[390／顶部安全区 47px](../../../../tests/visual-evidence/v17-game-390-safe47.png)。本目录的两尺寸整屏原画样稿与 0／4／12 状态保留作比例与角色基准；其 CSS 字形比运行时小，不作为最终字标素材。

## 逐图结论

- **320×568、安全区 46px：**4 和 12 连击均可读。12 连击时数字靠近关卡牌，但没有覆盖边框；右侧 COMBO! 与分数牌之间仍有留白。没有连击时应隐藏整个字标与数字，保持中间空白。
- **390×844、安全区 47px：**字标与顶部两牌的视觉重量平衡，没有压过规则卡。保留该版的字重、黄色／橙色层次和白色贴纸外缘。
- **规则卡间距：**按当前 renderer.js 的安全区 46px 布局，顶部牌的 y 约为 59–97，规则卡从 y≈102 开始。透明字标源的可见像素在现有 artY／artH 映射下最低约到 y≈99，因而现状尚未碰到规则卡，但仅有约 3px 的安全余量。390、安全区 47px 时该余量约 7px。320 下建议将字标绘制位置整体上移 2px，并且接续弧线只覆盖现有金色弧线的内部，不向下另加一条线；这样最低可见像素与规则卡之间约有 5px。

## 接续时间的非文字表达

v17 透明字标已有一条金色弧线，但目前它是静态图片，不表示剩余接续时间。保留它作为底纹；在其内部从左到右绘制 2px 的暖橙色弧线，长度取现有 comboWindow.remainingPercent。不要在字标下方新增条形轨道，也不要恢复“接续 X.X 秒”。

建议的 320 逻辑像素落点以现有 artX／artY／artW／artH 为基准：弧线左端约为 (artX + 0.41 artW, artY + 0.84 artH)，右端约为 (artX + 0.86 artW, artY + 0.84 artH)，中段上拱约 0.12 artH；线宽 2px。390 可等比放大到 2.5px。这个覆盖路径的最低点在 320 约为 y≈95，距规则卡上缘约 7px。接续窗口结束时橙色覆盖消失，底纹金线仍保留；连击本身归零时整组隐藏。

## 接入边界

沿用运行时现有透明素材 combo-wordmark-v17.png 和动态数字绘制；本目录的 draw-combo-mark.mjs 是不加载位图时的代码字形备选，不需要与 v17 图片叠画。角色、按钮、规则卡和底部风景不因这次连击定稿而重绘。接入动态弧线及上移 2px 后，再以微信开发者工具和真机截图核对 320 安全区下的最低像素间距；本审阅基于浏览器 Canvas 运行图。

## Mac启动步骤

需要Git、Node.js 20+（CI用24；优先已有兼容Node）、Mac版微信开发者工具。以下均为仓库根目录相对命令，无Windows盘符：

```bash
# 新机器首次获取；已有克隆则跳过这两行
git clone git@github.com:onovich/ThatButton.git
cd ThatButton

# 已有克隆先确认没有自己的未提交工作，再拉取
git status --short --branch
git pull --ff-only origin main
git log -3 --oneline

npm run validate
npm run build
npm --prefix ports/wechat ci
npm --prefix ports/wechat run check
```

若SSH尚未授权，用自己的GitHub登录/SSH设置完成访问；不要从Windows复制上传密钥或账号会话。不要复制Windows的 `node_modules`（esbuild含平台二进制），按锁文件在Mac `npm ci`。

在微信开发者工具中导入 **`ports/wechat/build/`**（不是源码根目录），沿用工程生成的AppID和配置。用于真机的新包需要在Mac重新预览/上传；拉取Git本身不会更新手机里的旧版本。

浏览器布局预览可运行 `npm run dev`，以终端实际输出端口为准，打开 `/ports/wechat/preview.html`。可选重跑长局模拟：`node scripts/simulate-late-difficulty.mjs`，会更新已跟踪的JSON结果，确有需要才跑。

### Git与同步边界

- `.codex/project-git-workflow.json` 和 `.cmd/.ps1` 包装器是Windows机器配置，不可直接在Mac照搬。Mac使用上述跨平台验证命令和标准Git；只暂存明确属于本任务的路径，普通提交/推送，不force-push。不要为适配Mac覆盖仓库里的Windows机器配置；需要Mac专用技能时使用该机器自己的配置。
- `main` 的push会触发现有GitHub Pages工作流，可能更新Web在线版；微信小游戏不会自动上传/发布。
- Git同步代码、已跟踪素材、方案和报告；不自动同步Codex聊天记录/子代理、浏览器登录、手机本地诊断数据、`node_modules/`、`dist/`、`ports/wechat/build/`、`output/`。本交接提供继续工作的必要上下文。
- 当前两批用户文字A/B JSON的结论已记录，完整粘贴原文并未额外存为仓库原始报告；不要声称能从仓库复原所有原始样本。旧Mac CPU采样已有独立跟踪文件。

## 手机操作：四轮 A → B → B → A

1. 用无 `perf`、`ruleAtlas`、`numberAtlas` 参数的普通预览进入游戏。首次进入默认关闭诊断与图集。
2. 首页「设置」→「内测诊断」→「同包文字A/B对照」→「A组：原文字绘制」，确认。等待「A组已就绪，请开始游戏」，返回首页开始。
3. 建议先做短测：每轮从第 1 关打到第 10 关，到第 10 关停止点击，让倒计时结束。若提前失败，记下关卡，并尽量让其余轮覆盖相近关卡。各轮保持相近点击节奏和相同升级选择。固定种子保证相同决策路径的随机内容可对照，人工操作仍不是逐帧回放。
4. 结算后回首页、设置，选择下一组。顺序为 **A、B、B、A**；中间连续两轮 B 也要重新选择 B，才会建立新的采样记录。选择新组会自动保存上一轮报告，局内及失败过渡期间禁止切组。
5. 四轮结束后，在对照菜单选择「退出A/B，恢复默认绘制」保存最后一轮；再选「复制本次A/B对照报告」。把剪贴板的一份 JSON 发给开发者，附上每轮实际关卡、时长和发热体感。

只保留最新 **4** 份会话报告，所以完成后先导出，再开始第五轮。请在关闭或重启游戏前导出：同包对照分组仅属于本次运行，重启默认关闭；旧的单份报告仍可通过「复制最近内测报告」读取。清除内测记录会删除这些报告，不会删除游戏存档；若要恢复默认绘制，另选「退出A/B」。

## 保持条件接近

两组都会自动开启同一套诊断、使用固定种子 `text-atlas-ab-v1`（有自定义 seed 时沿用该 seed），并在采样前加载同一张图集。A 也保留已解码图片，以减少图集加载与资源占用对绘制比较的干扰；这组测试不测默认关闭时的额外内存差异或冷启动加载成本。退出对照后释放图片引用。

手机亮度、音乐/音效、网络、微信模式与是否连接调试器保持一致。每轮开始前采用相同的休息方式，让手机回到接近的体感温度；不要只在某一组之前额外降温。A→B→B→A 可以减小测试顺序的偏差，仍不能完全排除设备负载与发热干扰。普通预览与连接真机调试的结果分开记录。

先确认四轮都能正确采集、B 有图集命中，并检查 B 的字形、字号、换行和高亮是否可接受。之后才做较长的发热/电量对照，例如每轮 10–15 分钟、相近关卡范围、不充电、各轮同样冷却。不要把一次体感变化当成温度测量。

## 报告如何判断

导出包含每轮原始 `reports` 和按场景归一化的 `rows`，会标明组别、顺序、构建指纹与种子。首先确认 `sameBuildAndSeed` 和 `hasBothGroups` 都为 true，再比较相近关卡的局内场景；首页/设置等待不混入局内比较。

- `drawMeanMs`：累计同步绘制提交均值，越低通常越有利；不是 GPU 完成耗时。
- `fillTextPerDraw`：每次绘制的文字调用数。B 应减少，同时 `ruleAtlasHit` / `numberAtlasHit` 应出现命中；只是路径生效证据，不等于性能收益。
- `rafOver50Percent`：超过 50ms 的 RAF 回调间隔占比，与总绘制次数、实际关卡和两轮重复结果一起看。
- `drawRecentP95Ms`：各轮该场景最近最多 256 个样本的 P95。尾部停手等待会影响它，不能当成整轮 P95，也不合并不同轮的 P95。

报告保留每轮结束时的 seed、关卡与分数，方便检查是否可比；不会自动宣布 A 或 B 胜出。没有实测 CPU 百分比、GPU 呈现 FPS、内存占用或手机温度。

## 本地验证边界

已覆盖同一个游戏实例 A/B/B/A 分组、固定种子、四份报告独立保存与合并复制、局内切换拦截、图片加载失败/加载期间开始游戏、退出恢复默认以及默认不开启。真实无头 Canvas 在两尺寸 × DPR 1/2/3 共 6 种组合下，对同一规则及同一 glitch 时刻做 A→B→A，恢复 A 均与旧基线 0 像素差异，见 [切换结果](wechat-text-atlas-2026-10-02/runtime-switch-results.json)。

B 的字体仍存在已知视觉差异。这些检查证明切换与采集机制可用，不是微信真机性能验收。

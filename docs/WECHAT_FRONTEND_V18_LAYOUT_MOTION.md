# 微信小游戏 v18 布局与动效验收

日期：2026-09-30。本轮基于已签收的 v15 整屏原画、v11 角色基准和 v17 `COMBO!` 字标，处理局内对齐、无连击留白及各页面交互反馈。运行时实现位于 `ports/wechat/src/renderer.js`，不改变 Web 端玩法。

## 原画补稿

已请原画负责人在**完整局内画面**上设计无 Combo 状态，而非单独绘制浮动贴纸。交付见 [0／1 连击整屏稿及逐帧规格](../ports/wechat/assets/concepts/2026-09-30/combo-idle-motion/README.md)：

- 0 次：低于关卡牌和分数牌权重的闪电、淡金 `READY` 与静态金色弧线，不显示虚构倒计时。
- 1 次：暖橙阿拉伯数字与 `HIT!`，弧线内部由真实接续剩余比例驱动。
- 2 次以上：沿用 v17 透明 `COMBO!` 字标与动态数字。

已检查交付的 320×568／安全区 46px 和 390×844／安全区 47px 各四档整屏稿，并将原画的 Canvas 绘制规格接入 [pre-combo.js](../ports/wechat/src/pre-combo.js)。0、1、2、12 连击的运行图都无相邻牌或规则卡遮挡。连击结束时原字标在 220ms 内线性缩小并淡出，新兜底稿同时淡入。

## 布局和视觉细节

- 分数牌以 Canvas 实测字宽，将“数字＋分”作为一个整体居中；分数位数增加时逐级缩小字号，`123456 分` 的 320 宽度压力图仍在框内。
- 每个实体按钮的图案、间距和两位数字作为一个垂直组合在按钮正面居中；按下时组合随按钮正面一同下陷，保持相对位置。
- 首页主按钮补足深蓝边和青色侧壁；局内规则卡、九宫格、角色与底部体力／挑战进度牌沿用已验收的整屏比例。倒计时危急时轻脉动，体力、挑战进度与分数变化都有数值缓动和短脉冲。
- 误按红边在 700ms 内略向外扩张并淡出；相机震动期间命中检测同步扣除画面位移，避免视觉位置和可点区域错开。

## 动效语言

统一使用三次方插值入场、轻微缩放过冲复位和透明度插值。只有有意义的事件使用相机震动，不做持续摇晃。

| 交互／状态 | 反馈 |
| --- | --- |
| 首页、结算标题与角色、帮助／设置卡、升级卡、返回前台弹层 | 错峰缩放入场，轻过冲后复位并淡入；帮助／设置卡保持稳定可读 |
| 主按钮、返回按钮、设置开关 | 按下回缩和回弹；开关钮在 320ms 内按插值移动 |
| 安全按钮 | 凸起到凹陷约 245ms，成功描边放大淡出约 430ms；分数／体力／挑战进度数字插值约 390–450ms |
| 误按、考官进度命中、体力耗尽 | 分别采用强弱不同、随时间衰减的短相机震动；误按按钮本身短促横摆 |
| 连击与升级选择 | 连击字标弹入、奖励脉冲；连击结束缩小淡出；升级卡依次弹入，选中卡短促放大复位，其他卡降低权重 |

相机震动、位图位移和 Canvas 动效只在具备完整变换接口时启用；`motionEnabled: false` 可回退静态画面。后台时暂停帧循环，返回前台后重新绘制。动效采用 32ms 活跃更新与 85ms 环境帧更新，避免每帧都以最高频率重绘。

## 角色逐帧

根据原画负责人的 [逐帧规格](../ports/wechat/assets/concepts/2026-09-30/combo-idle-motion/character-motion-spec.json)，[character-frames.js](../ports/wechat/src/character-frames.js) 将现有透明图编排为离散关键帧：

- 首页奔跑双人组：8 帧、12 fps，整组绕鞋底附近轻微上浮／旋转。
- 局内双角色：8 帧、8 fps，沿透明空隙切成左右两个源矩形，错峰轻浮动。
- 结算安慰双人组：稳定 300ms 后，6 帧、6 fps 轻呼吸循环，保持扶头接触关系。

这些帧均取自已验收的 v11 透明角色 PNG，仅做刚体位移与轻旋转，未重新生成人脸、四肢或描边。当前合成图没有独立肢体图层，真正交替迈腿／拍头动作需要原画另行提供逐帧手绘分层母版。
